# 专家项目全阶段 Prompt 结构示例

这是项目定向完成后的一套结构示例。它只展示怎样让学艺者把完整来源读成可复用的判断方法，不携带领域术语、固定主题或机器流程。

每个阶段除指令外，还应给出“输入片段 -> 合格输出”的少样本示例，让模型不是猜测标准，而是模仿已经验证的判断深度。下文示例全部标注“只示范结构与判断深度，不是当前材料的检查清单”；示例里的具体词只是占位，不得被当成后续单篇材料必须出现的检查项。

## 材料侦察

```text
完整阅读用户确认的代表材料，辨认材料形态、作者判断、提问、反馈和转写噪音。样本只用于决定后续怎样学，不把样本术语、案例类型或顺序变成其他材料的检查清单。形成可供用户展开查看的定向依据，不提前写笔记或主题目录。
```

## 项目学习方案

```text
向用户说明这批材料将学习什么判断方法、材料范围与边界，以及完成后能帮助读者处理什么问题。内部角色、阶段交接和编译指令写入编译底稿或阶段 Prompt，不进入用户学习方案。
```

## 单篇学艺

```text
你正在向当前材料中的作者学习判断。完整读完自然材料，区分作者判断、提问、反馈和转写噪音。找出作者实际观察的结构或信号、作出的判断或取舍、材料明说的理由，以及会改变处理的条件。

保留作者明确提出的术语、口诀、公式、经验口径、特殊关系和操作方法，并写清材料已经说明的含义与条件。不得因为这些内容只出现一次、不能由常识推出或外部资料没有印证就删除，也不得补写材料没有解释的理论。

笔记正文只写自然 Markdown，不输出 JSON、字段说明、原文行号、审稿意见、修订过程或处理状态。案例过程和行号留给证据字段，正文只保留后续主题整理真正需要的判断。

内部执行步骤（只示范结构与判断深度，不是当前材料的检查清单）：
① 通读全文，标记作者判断、提问、反馈与转写噪音；
② 逐段提炼判断链：结构或信号 -> 作者如何判断或取舍 -> 理由或经验依据 -> 改变处理的条件；
③ 筛选，只保留会改变下一次判断、动作、适用条件或判断依据的内容；
④ 整理为自然 Markdown 笔记与响应字段。

少样本示例（只示范结构与判断深度，不是当前材料的检查清单）：
输入片段：师傅说“出门前先看天色和当天预报；只是多云但风不大，可以不带伞；一旦预报有阵雨，就带上伞；要是已经在路上，按‘宁带不用’处理。”
这一步学到的不是“多云”“阵雨”这些词，而是判断链：先看什么信号（天色、预报） -> 怎样取舍（多云且风小可不带） -> 理由（降低被淋风险也减少负担） -> 改变处理的条件（预报有阵雨、已经在路上则宁带不用）。
由此写出的笔记只保留可迁移的判断，不把“多云”“带伞”当成其他材料必须出现的检查项。
```

## 笔记 Review

```text
先独立完整阅读当前材料，再完整阅读笔记。核对作者判断、明确术语、经验口径、理由、条件、例外和停止线是否遗漏或失真；检查个案是否被拔高为无条件通则，外部理论是否混入，证据是否真的支撑对应判断。

可以在内部建立核对清单，但最终只输出通过，或会影响后续学习、合成和使用的具体问题及修订方向。不要输出审稿过程，不要为不影响下游的措辞偏好要求修订。

内部执行步骤（只示范结构与判断深度，不是当前材料的检查清单）：
① 独立完整阅读原文，先形成自己的判断链理解；
② 逐条核对笔记中的信号、判断、理由和条件是否忠实；
③ 检查：个案是否被拔高为无条件通则、外部理论是否混入、证据是否真的指向对应判断；
④ 只输出通过结论，或会影响后续学习的具体问题与修订方向。

少样本示例（只示范结构与判断深度，不是当前材料的检查清单）：
输入核对：上面“带伞”例子的对应笔记把“预报有阵雨就带伞”写成了“雨天必须带伞”，且删掉了“已在路上则宁带不用”的条件。
发现的问题：把有条件的建议升级成了无条件通则；未保留改变处理的条件。
合格 Review 输出只给业务结论，例如：
decision: revise
issues: [{problem: "把有条件的建议升级为无条件通则", affected_part: "判断链的‘改变处理的条件’环节", source_lines: ["L4"], revision_direction: "恢复‘预报有阵雨才带伞，已在路上时宁带不用’的条件表达"}]
“通过”与“无迁移价值”也要给出对应形态，避免只输出某一种结论。
```

## 笔记修订

```text
回到当前完整原文，只落实有来源支持的具体修订。保留作者判断、明确术语、经验口径、理由、条件和证据强度；删除个案通则、外部补写和过程文字。输出仍是自然 Markdown 笔记与既定响应字段，不复述 Review 或修订过程。
```

## 主题候选研究

```text
先用来源级路标召回可能相近的笔记，再完整阅读这些笔记。按读者真实问题比较判断主干、条件分叉、冲突和材料支持的组织方式；不能统一的差异保留，不宣布最终主题。
```

## 总编主题地图

```text
按读者真实会遇到的判断问题决定主题边界和顺序。主题标题不写材料目录或百科类目。只有笔记明确支持时才合并相近判断或形成分类，材料不足时保留差异，不为了整齐补造结构。
```

## 总编讲义

```text
先说明本章解决什么问题、何时需要使用；再按结构或条件、作者判断、理由与使用边界写出判断主干。章首列出本章的知识单元清单：每条是“局面 -> 判断 -> 边界”的一句话，正文把它们展开为带条件的判断动作。保留会改变使用的术语、经验口径、公式、顺序、条件和反转；案例退居说明位置并用编号引用，同一案例事实不在多章复述。检验标准是价值密度：抽掉案例后，本章应剩下读者能在新局面上使用的判断动作；剩下的只有证据批评时，把内容收窄为相关判断的启用条件。

内部执行步骤（只示范结构与判断深度，不是当前材料的检查清单）：
① 明确本章解决的读者问题与适用时机；
② 列出本章知识单元清单；
③ 按“结构或条件 -> 判断 -> 理由与使用边界”展开每个单元的判断主干；
④ 案例退居说明位置、证据退居支撑位置；
⑤ 检查条件分叉与反转是否保留，抽掉案例后是否仍有可迁移的判断动作。

少样本示例（只示范结构与判断深度，不是当前材料的检查清单）：
输入片段：多份笔记都涉及“怎样判断当天要不要带伞”，一份强调看天气信号，一份补充了“已在路上”的例外情况。
这一步不是把两篇笔记轮流复述，而是组织成：什么时候需要判断 -> 先看什么信号 -> 怎样取舍 -> 什么条件会改变处理 -> 例外怎么处理；天气信号和路上的例外分别放进判断主干和条件分叉。
```

## 讲义 Review 与修订

```text
检查讲义是否教会判断主干、材料明确知识和条件分叉，只报告会让读者学错方法的具体问题。修订只处理这些问题，不因文风偏好重写，也不在材料不足时强行分类。
```

## 全书收口、导航与最终 Skill

```text
全书收口做跨篇的术语统一、冲突并陈、重复消除和缺口登记；案例事实只在全书统一的出处索引中详述一次，各处编号引用。导航按读者真实局面组织：局面线索 -> 知识单元 -> 展开层锚点，让运行时模型按局面勾选进入，而不是从头阅读。最终 Skill 写成使用协议：专家身份与口吻、遇到新局面的查询步骤、常见误判的纠正表、明确不做的事；它继承已确认的专家姿态、判断方法、材料明确知识和停止边界，不新增材料没有的规则。
```
