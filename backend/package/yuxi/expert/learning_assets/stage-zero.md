# 第 0 阶段：材料侦察与学习方案确认

第 0 阶段的目标不是直接写专家 Skill，而是回答：这批材料应该怎样学，才不会把老师的手艺读成通用摘要。

## 流程

```text
已经转成可靠正文的自然材料单元
-> 多个侦察任务并发阅读各自的一小组完整材料
-> 每个侦察任务交一份短报告
-> 一个汇总任务阅读全部侦察报告
-> 生成项目学习方案和推荐小样
-> 1-2 份真实材料写笔记并 review
-> 用户确认后进入批量学习
```

## 侦察任务怎么分配

- 一个侦察任务只接收自己被分配的完整材料单元，不能读取项目目录或其他批次材料。
- 分组大小由每份材料的实际长度和模型可读范围决定，不把“每组五篇”写死为规则。
- 首次试跑可以从约五到六组开始；每组装入若干完整材料，直到仍能完整阅读为止。
- 材料已经是自然单元时，不按字符数再次切分。过长材料应在进入本阶段前明确拆成有业务意义的单元，或标记为需要处理。

## 侦察报告要回答什么

每个侦察任务只说明自己实际读到的材料：领域和语体、说话人关系、可迁移判断的形态、材料之间的差异或冲突、阅读时必须遵守的纪律，以及适合做小样的材料和原因。

它不写正式讲义、不预设最终主题树，也不因为没有读到的内容而替整个项目下结论。

## 汇总任务要做什么

汇总任务读取所有侦察报告和中央学习方案模板，产出一份可展示给用户的项目学习方案。它需要明确：

- 这批材料是什么、谁在说话、应该怎样区分事实与噪音；
- 要学的判断方式和不应补造的内容；
- 笔记、review 和讲义各自要注意什么；
- 哪些冲突必须并列保留；
- 推荐哪 1-2 份材料做笔记小样，以及推荐原因；
- 哪些问题尚未看清，不能假装已经确定。

汇总任务只依据侦察报告，不应重新猜测没有证据的材料内容。报告出现分歧时，应保留分歧并说明需要用小样验证什么。

## 用户确认点

系统用推荐材料运行笔记作者和笔记 Reviewer，展示项目学习方案、笔记小样和 review 结果。用户确认“这样学习对不对”后，项目学习方案才固定并进入第 1 阶段。

用户不同意时，系统基于明确反馈修改学习方案并重新跑小样；不会直接批量处理全部材料。
