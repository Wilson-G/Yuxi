# 领域推导资产项目全阶段 Prompt 结构示例

本文件由 `reasoning_assets` profile 注册项显式加载。它展示如何把中央方法改写成项目专属的
11 阶段 Prompt，并用两份真实 Amazon 运营材料校准资产结构和证据边界。

Amazon 示例只示范结构、来源拆分、补链尺度和 Review 深度，不是当前项目的领域知识来源，
不是其他领域或其他 Amazon 材料的检查清单。生成项目 Prompt 时必须换成当前代表材料实际使用的
领域语言；不得复制这里的指标、阈值、工具、动作或结论。

## 第 0 阶段：领域激活与材料校准

项目专属定向 Prompt 应明确要求模型按下面顺序工作：

```text
1. 只根据项目说明与材料目录，先激活模型已有的领域判断地图。
2. 把这张地图标为模型已有知识，不得写成材料原话。
3. 再完整阅读用户确认的代表材料，记录实际语言、判断跳步、覆盖、冲突、专业问题和未知。
4. 用材料校准“后续怎样学”，不提前为全部材料写笔记或主题。
5. 交付用户学习方案、内部编译底稿和完整 ProjectPromptPack。
```

项目学习方案应自然说明：系统会保留材料主张，允许用领域知识补足必要中间关系，
同时把专业质疑和材料没有回答的部分分开。它不向用户介绍节点字段或内部角色。

内部编译底稿应保存当前项目的领域判断地图、材料校准结论、四类来源边界、各阶段职责、
Review 标准和最终回答边界。中央示例中的领域内容不能进入底稿。

## `note_author`：完整材料编译为资产

项目专属 Prompt 应要求 Author 返回现有 `MaterialNoteResult`，其中完整资产写入 `note_markdown`。
下面使用真实材料《每天一个亚马逊运营技巧ACOS太高怎么办？》校准格式。

材料直接给出：

- ACOS 等于广告花费除以广告销售额；
- 广告花费等于点击次数乘 CPC；
- 广告销售额等于点击次数乘转化率乘客单价；
- ACOS 高时不要只看总数字，要检查点击量、转化率、自然流量占比和搜索词表现；
- 材料案例记载，团队降低预算后订单和流量下降；
- 材料建议把无效流量预算转向高转化词。

合格的 `note_markdown` 片段：

```markdown
# ACOS 异常的领域推导资产

## 资产定位
这份材料处理 ACOS 升高时是否应立即缩减总预算的问题。它提供诊断顺序和预算转移思路，
但部分算法因果、固定阈值和收益承诺缺少完整条件。

## 资产节点目录
- N01 [输入事实][原文明说] 材料给出 ACOS、广告花费和广告销售额的关系
- N02 [连续推导][领域补链] 消去点击次数后明确公式中的括号关系
- N03 [条件分支][原文明说] 按点击、转化、自然流量和搜索词表现区分动作
- N04 [反馈/回验][原文明说] 材料记载降低预算后订单与流量同步下降的团队案例
- N05 [连续推导][原文明说] 材料主张点击骤降会使算法判断活跃度不足并导致排名后撤
- N06 [专家质疑][专家质疑] 公式表达和案例因果缺少必要边界
- N07 [反转/停止][原文明说] 广告关闭仍亏损时转向定价与成本结构
- N08 [预测/未知][材料未知] 固定阈值的适用范围、排名恢复和后续利润没有独立回验
- N09 [可迁移检查][领域补链] 动作前补齐利润边界、流量趋势和词级表现

## 资产正文

### N01 [输入事实][原文明说]
材料把 ACOS 定义为广告花费除以广告销售额，并分别写出广告花费等于点击次数乘 CPC、
广告销售额等于点击次数乘转化率乘客单价。这些是材料直接给出的关系；归属清楚不等于公式表达已经无歧义。

### N02 [连续推导][领域补链]
由材料给出的两个等式消去点击次数，可写成 `ACOS = CPC /（客单价 × 转化率）`。
这里只补出数学上必要的括号关系，不把它写成作者逐字原话。

### N03 [条件分支][原文明说]
材料要求先看过去七天点击量是否增长、转化率是否稳定、自然流量占比是否上升，
再区分继续爬坡、处理低转化或清理无效搜索词。材料主张真正控成本时控制无效流量，
把预算转向高转化词，而不是条件反射削减总预算。

### N04 [反馈/回验][原文明说]
材料记载一个正在爬坡的团队产品在同事降低预算后，订单下降三分之二并持续四五天。
这只保留材料中的案例反馈，不把相关性升级为已隔离其他变量的因果实验。

### N05 [连续推导][原文明说]
材料主张推广爬坡期需要稳定点击量维持平台算法认知；点击量断崖式下降后，
平台会判断产品活跃度不足，关键词排名随之后撤。这是材料直接给出的因果链。

### N06 [专家质疑][专家质疑]
原转写“CPC 除以客单价乘转化率”缺少括号，按不同运算顺序会得到不同结果。
团队案例也没有同时控制竞价、库存、竞争环境、转化变化和观察窗口，不能单独证明 N05 是唯一机制，
更不能保证任何产品恢复预算后排名必然恢复。

### N07 [反转/停止][原文明说]
材料提出：如果关掉广告后产品仍然亏损，问题已经转向产品定价和成本结构。
这构成继续扩量前的停止条件，而不是继续增加预算的理由。

### N08 [预测/未知][材料未知]
当前材料没有提供各固定阈值的类目适用范围和样本来源，
也没有提供自然排名稳定后 ACOS 回落的独立回验。因此这些数字的迁移范围和后续效果仍然未知。

### N09 [可迁移检查][领域补链]
迁移到新问题时，先核对当前利润边界、预算是否实际受限、点击与转化趋势、自然和广告流量变化、
搜索词相关性及词级订单表现。缺少这些输入时先追问或缩小动作，不把“ACOS 高”直接翻译成加预算或减预算。
```

对应的外层字段应保持原职责：

```text
decision: learned
routing_labels:
  - ACOS 高不等于立即削减总预算
  - 先看点击量、转化率和自然流量占比
  - 控制无效流量并转移预算
candidate_questions:
  - ACOS 升高时应该先检查什么，再决定是否调整预算？
  - 怎样区分推广爬坡和无效广告消耗？
evidence:
  - 只引用支持 N01、N03、N04、N05、N07 等材料明说节点的真实行号
  - 不为 N02、N06、N08、N09 伪造原文依据
```

## `note_reviewer`：独立复核来源和领域关系

项目专属 Prompt 应要求 Reviewer 先独立阅读完整材料，再核对每个节点。Review 的硬问题包括：

- 原文公式是否被误写，材料主张是否被补链覆盖；
- 领域补链能否由输入事实和稳定关系推出，是否存在方向写反；
- 案例相关性是否被升级成唯一因果；
- 固定数字、平台规则和未来效果是否缺来源或适用条件；
- 强动作是否只建立在候选解释上；
- `evidence` 是否只锚定材料明说。

链更长不等于质量更高。Reviewer 必须尊重用户输入事实，检查反领域关系，
并拒绝让候选解释支撑强动作。

第二份真实材料《亚马逊产品转化差怎么排查问题》用于校准 Reviewer：材料明确提出
“Listing 九要素 -> 广告优化 -> 产品竞争力与止损”的顺序，也出现“90%”“0.02 秒”“95%”、
评分差异对应固定转化倍数等无来源数字。合格 Review 应保留这些内容为 `原文明说`，
同时建立 `专家质疑` 节点说明缺少来源和适用范围；不能静默删掉数字后把结论继续写成已证事实。

材料还说“永远先查产品，再查广告”，但同文又要求检查搜索词相关性和泛流量。
领域补链可以把“没有点击”“流量不相关”“相关点击不出单”分成不同诊断入口；
它不能冒充作者原话，也不能把新的分流顺序写成唯一平台规则。材料末尾提醒高客单价决策周期和广告归因延迟，
但没有给出统一等待窗口，因此具体窗口仍属于 `材料未知`。

## `note_reviser`：按问题重建完整资产

项目专属 Prompt 应要求 Reviser：

```text
回到完整原文
-> 保留被质疑的原文明说节点
-> 把混写内容拆成原文明说、领域补链、专家质疑或材料未知
-> 修正错误的领域关系和过强动作
-> 重建完整资产节点目录与正文
-> 返回同一个 MaterialNoteResult 合同
```

不要输出 Review、修改摘要或“已修正”。无反馈材料不增加反馈节点，无预测材料不增加预测节点。

## `topic_researcher`：目录召回与组内完整研究

同一项目 Prompt 要适配两个现有任务：

```text
全局规划输入
= routing_labels + 每份资产的“## 资产节点目录”
-> 只形成有意义的完整阅读范围，不宣布正式主题

组内研究输入
= 当前范围内的完整资产正文与来源映射
-> 比较连续判断链、分支、反转、停止、动作依据、冲突和未知
-> 提交候选主题给总编
```

不能按来源标签各建一类，也不能只凭节点摘要合并观点。

## `topic_editor`：总编决定主题地图

项目专属 Prompt 应要求总编按真实读者问题决定主题边界和顺序。相近资产只有在输入前提、
判断主干和动作条件能够兼容时才合并；材料主张、领域补链、专家质疑和材料未知保持可区分。
全部核心链都无法成立时，可以明确不采用，不能为满足主题数量补造结构。

## `handout_editor`：编成模型可学习的连续判断

项目专属 Prompt 应要求讲义包含：适用局面、必要输入、判断主干、条件分支、反转或停止、动作依据、
反馈怎样修正前断，以及当前未知。可以选择少量完整资产作为 CoT 学习示范，
但不得把节点标签设计成用户回答模板。

成稿前检查：链更长不等于质量更高；用户输入事实不能被示范覆盖；领域关系不能写反；
候选解释不支撑强动作。

## `handout_reviewer`：只拦会让模型学错的问题

Reviewer 核对讲义是否混淆来源、遗漏分支或停止、删除真实质疑、把预测写成回验、
或让动作超过已经成立的链。关键材料结论必须位于证据包允许的范围。

链更长不等于质量更高。Review 必须尊重用户输入事实、检查反领域关系，
并拒绝候选解释支撑强动作。标题偏好和缺少可选栏目不构成修订理由。

## `handout_reviser`：定点修订讲义和编辑方案

总编只落实具体 Review 问题，同时提交修订后的完整讲义和下一版完整编辑方案。
不得借修订重写无关内容，不得把未知补成确定结论，也不得删除来源边界来换取流畅。

## `book_editor`：全书一致性收口

全书检查同一术语和领域关系是否方向一致，同一结论的来源强度、条件、反转、停止与动作口径是否一致，
多来源冲突是否被保留。链更长不等于质量更高；发现多推一步时应删除或降调，
不能为了显得完整继续延长作用链。

## `navigation_author`：按真实判断局面导航

导航使用读者问题、输入信号、条件分支和停止线帮助运行时模型定位讲义。
导航不得暴露节点 ID、来源标签、审计锚点、文件路径或编译过程。

## `skill_author`：生成自然回答边界

最终 Skill 要让 Agent 从当前用户事实主动建立观察，检索相关讲义和少量推导示范，
学习检查顺序而不是复制示范答案；新反馈到来时确认、削弱或改线。

成品阶段必须写明：

```text
链更长不等于质量更高。
当前用户输入事实高于任何相似案例。
不得写反领域关系。
候选解释不支撑强动作。
最终用户回答自然完整，不输出节点 ID、来源标签、Thought、Action、审计路径、文件路径或编译说明。
```

## 完整 `ProjectPromptPack` 检查

交付前逐项确认下面 11 个字段都是当前项目可直接执行的完整 Prompt，而不是占位说明：

```text
note_author
note_reviewer
note_reviser
topic_researcher
topic_editor
handout_editor
handout_reviewer
handout_reviser
book_editor
navigation_author
skill_author
```

每个 Prompt 使用当前项目的领域语言。Amazon 校准样例中的 ACOS、Listing、广告指标、固定数字和动作
不得进入其他项目，也不得成为同领域后续材料必须出现的检查项。
