# 知铸 ZhiForge

知铸（ZhiForge，仓库与技术标识暂保留 `Yuxi`）是一个基于大模型的专家学习与 Skill 编译平台。它的默认产品对象是“专家项目”：用户导入一批可靠材料，系统把材料中的判断方法、成立条件、例外和真实边界学习为独立、可启用的专家 Skill。

这条流程不是把文档切块后生成摘要，也不是为整份原文建一个检索索引。最终专家应该能够解释“看什么信号、怎样得出判断、什么条件下成立、遇到冲突和例外时怎么处理”。

## 默认用户流程

1. **材料转正文**：PDF、Office、Markdown 和图片等原始文件先转成模型可靠阅读的完整正文。
2. **项目定向**：系统阅读材料目录、基础信息和用户选定的、最多 20 份且覆盖不同方向的代表性材料，由总编模型形成项目学习方案和项目专属 Prompt 包。
3. **第一次确认**：用户查看学习方案、笔记小样和 Review，确认“这样学对不对”。
4. **批量学材料**：普通模型任务按自然材料单元并行完成笔记、Review、最多两次自动修订和复核。
5. **组织主题**：并行助手准备候选主题、证据和冲突清单，项目内串行的总编模型形成统一的主题地图、编辑方案和讲义小样。
6. **第二次确认**：用户确认“这样组织和表达对不对”，之后系统才批量编写正式讲义。
7. **总编成书**：总编模型逐篇定稿，再检查全书术语、冲突、重复、缺口、导航和回答口径。
8. **预览并启用**：系统生成候选专家 Skill，用户预览成品和未纳入材料清单后手动启用。

两个确认点都是默认必经步骤。普通材料 Review 在后台最多自动修订两次；正文无法可靠读取、任务持续失败或两次修订仍不通过时，项目会明确停下。

## 模型与系统的分工

| 职责 | 承担者 |
| --- | --- |
| 完整材料阅读、笔记、Review、证据准备 | 普通模型任务，不同材料可并行 |
| 学习方案、主题地图、讲义正式稿、全书收口 | 同一项目内串行执行的总编模型 |
| 项目范围、状态、恢复、门禁和发布 | 知铸系统 |
| 学习方向与知识组织方式 | 用户在两个确认点决定 |

第一版总编直接复用知铸已配置的模型。Prime 是后续可选的总编执行者增强，不是当前主流程的前置依赖。

## 最终交付

发布物是一个普通、独立的 Skill：

```text
skill/<name>-expert/
  SKILL.md
  nav/
  references/
  wiki/
  search/
  sources.jsonl
```

`wiki/` 保存经过 Review 的正式讲义，`references/` 保存足以支撑关键判断的精选证据，`sources.jsonl` 保存来源与引用映射。原始上传文件、整份可靠正文、项目 Prompt、Review、失败记录和任务进度不会进入最终 Skill。

启用后，Agent 只读取该 Skill 中的讲义、导航和精选证据，不绕过 Skill 访问编译项目中的原始材料。

## 运行边界

- 专家项目记录是阶段、进度、产物和恢复的事实来源。
- ARQ worker 负责跨进程执行和服务恢复后的未完成工作重投。
- 任务中心只展示项目摘要，不承担专家项目恢复。
- 旧知识库、向量检索和知识图谱作为兼容能力保留，需要时显式启用；新专家项目不进入其分块和入库链路。
