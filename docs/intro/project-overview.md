# 什么是知铸？

知铸 ZhiForge 是一个专家 Agent 制造平台。它把文章、课程、讲义、案例和企业经验转化为能够理解方法、做出判断并解释依据的专家大脑。

传统知识库擅长保存和检索知识，但“找到相关内容”不等于“知道应该怎样判断”。知铸关注知识背后的专业能力：专家看什么信号、怎样分析、结论在什么条件下成立、遇到例外时如何调整，以及信息不足时为什么应该停下。

## 从材料到专家

知铸把文件处理与专家学习分开：

1. 管理员在资料库批量上传文件或目录，整理目录并查看逐文件处理进度。
2. 系统完成 OCR、解析和格式归一化，保存可核对的完整正文。
3. 长材料按真实内容形成自然主题材料单元；短材料保留完整正文范围。
4. 管理员从就绪材料单元创建专家项目，不重复上传或解析来源文件。
5. 项目先确认学习方向，再逐份学习材料；知识组织方式确认后形成专家 Skill。
6. 管理员预览成品并手动启用，再按已有共享权限分发给普通用户。

资料库是新增专家材料的唯一入口和正文事实来源。旧知识库、向量检索和知识图谱继续作为显式兼容能力，不是新增专家项目的依赖。

## 专家 Agent 的能力

- **理解方法**：读懂材料中的分析路径、判断顺序和实践经验，而不是只抽取事实。
- **形成判断**：面对具体情境识别关键信号，从现象走向结论。
- **懂得条件**：理解前提、例外、分歧和专业边界，知道何时改变判断。
- **解释依据**：说明为什么这样判断，并让关键结论回到可靠材料核验。

用户得到的不是一个会搜索文档的问答入口，而是一位能够运用材料中专业方法的专家 Agent。

## 比普通 RAG 更进一步

RAG 解决资料获取问题：根据问题找到相关片段，再让模型整理答案。它适合事实查询、文档定位和来源引用。

| 普通 RAG | 知铸专家 Agent |
| --- | --- |
| 找到相似知识片段 | 理解材料形成的知识体系和方法 |
| 围绕召回内容组织答案 | 结合信号、条件和经验形成判断 |
| 依赖当前片段是否覆盖例外 | 主动说明适用范围和反转条件 |
| 给出来源引用 | 同时解释判断逻辑、依据和边界 |

知识库、向量检索和知识图谱仍然可以继续使用。它们负责提供资料，专家 Agent 负责理解资料并做出专业判断。

## 适合制造哪些专家

- 把一位老师的系列课程与案例制造成师承型专家；
- 把企业制度、操作手册和项目复盘制造成业务专家；
- 把技术标准、设计文档和故障案例制造成技术专家；
- 把行业研究、咨询方法和访谈材料制造成领域专家；
- 把多位专家的不同观点制造成懂得区分条件的综合专家。

材料越能体现真实的思考过程和判断经验，最终专家越有价值。只有零散事实或重复资讯的资料，更适合放入普通知识库。

## 完整智能体平台

知铸也提供让专家进入真实工作的智能体基础：

- 基于 LangGraph 的智能体运行时；
- Skills、MCP、工具、子智能体和中间件；
- 沙盒文件系统、附件与可交付产物；
- 模型配置、后台任务和运行状态；
- 组织、部门、用户、共享范围与 API Key；
- Milvus 知识库、Dify / Notion 连接器与知识图谱兼容能力。

项目基于 Vue 3、FastAPI、LangGraph、PostgreSQL、Redis 和 MinIO 构建，并通过 Docker Compose 管理。仓库、Python 包、环境变量、API 和 CLI 等技术标识暂时继续使用 `Yuxi` / `yuxi`。
