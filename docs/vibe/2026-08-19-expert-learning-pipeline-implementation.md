# 专家学习与编译迁移实施设计

日期：2026-08-19

状态：第一版主链已完成

最高业务依据：[专家学习流程改造：意图冻结与共识说明](2026-08-18-expert-learning-pipeline-intent.md)

## 目标

把当前分支中尚未接线的项目 Prompt 设计资产，以及备份分支中的上传、ARQ、Skill 安装能力，迁移为知铸的专家项目主链：

```text
材料转可靠正文
-> 用户选择代表样本
-> 确认怎么学
-> 逐份学习和 Review
-> 确认怎么组织
-> 总编模型串行编讲义并收口
-> 预览并手动启用专家 Skill
```

第一版使用 Yuxi 当前配置的聊天模型承担总编职责，不接入 Prime。Prime 只作为后续替换总编执行者的增强，不进入本轮依赖、状态或 UI。

## 当前事实

- 专家项目模型、路由、ARQ Worker、任务中心投影和前端页面已经接通，项目记录是恢复和进度的事实来源。
- 第一阶段原型中只复用了安全接收材料、ARQ 注册、Skill 安装/启停和标准 Skill 运行时，没有迁移“复制全文、建立快速索引”的旧主链。
- 文档正文转换直接复用 `yuxi.services.ocr_service.parse_document()`；专家流程不调用旧知识库分块、Milvus 或 Neo4j。
- 普通模型任务并行学习、Review 和准备证据；当前配置模型作为项目内串行总编形成主题地图、讲义、导航和最终 Skill。
- 任务中心只展示项目记录计算出的进度；API 进程内 `Tasker` 不参与执行或恢复。

## 最小领域记录

### 专家项目

项目记录保存：名称、说明、模型、当前业务阶段、当前状态、两个确认版本、项目定向、学习方案、项目专属 Prompt 包、主题地图、编辑方案、最终 Skill 和可行动错误。

阶段与状态分开表达：

- 阶段：项目定向、材料学习、知识组织、讲义编译、发布。
- 状态：准备中、运行中、等待确认、需要处理、成品待启用、已启用。

这两个字段直接服务页面状态、恢复扫描和阶段门禁，不扩展为通用状态机。

### 材料

每个自然材料单元独立一行，保存原始文件与可靠正文路径、可见标题和来源路径、正文行数与 token 估算、当前处理结果、笔记、Review、一次修订结果和错误原因。

一份材料只会进入以下业务终态之一：

- 笔记通过；
- 明确没有迁移价值；
- 需要处理；
- 用户明确排除。

### 主题

第 2 阶段开始后，每个总编确定的主题独立一行，保存其笔记/证据范围、所属编辑分组、证据包、讲义候选、Review、一次修订和正式讲义。普通助手只写研究与 Review 输入，总编模型串行写主题地图、编辑方案和正式讲义。

## 阶段合同

### 第 0 阶段：项目定向和 Prompt 设计

输入：

- 用户可见的完整材料目录和基础信息；
- 用户明确选择的、最多 20 份且覆盖不同方向的代表性材料完整正文；
- 中央 Prompt 设计方法、一个匹配的材料类型模板和高质量示例；
- 用户对上一版的明确反馈（仅重新定向时）。

输出：

- 项目定向报告；
- 人可读的项目学习方案；
- 项目专属编译底稿和完整阶段 Prompt 包；
- 代表材料的笔记小样及独立 Review。

门禁：项目停在“等待确认”。用户确认后固定整个方法版本并进入材料学习；用户要求调整时创建新版本、重新生成小样，旧版不再驱动下游任务。

第一版不自动猜代表样本。用户从可见材料清单明确选择最多 20 份、覆盖不同方向的材料，避免按文件位置、字符数或其他隐藏启发式抽样。

### 第 1 阶段：逐份学习与 Review

输入：已确认的方法版本、单份完整可靠正文、该材料的可见来源信息。

输出：笔记、来源行号锚点、候选读者问题、召回路标、独立 Review，以及必要时的一次定点修订和复审。

执行：每份材料是一个独立 ARQ 工作；不同材料并发，同一材料内部串行。完成项不会因另一份材料失败或服务恢复而重跑。

门禁：存在“需要处理”的材料时不进入主题组织。用户只能重跑该材料或明确排除；被排除材料进入后续主题方案和成品预览的未纳入清单。

### 第 2 阶段：主题与讲义小样

输入：全部通过 Review 的笔记和明确未纳入清单。

输出：助手候选研究、总编主题地图、当前编辑方案、1～2 篇讲义小样及 Review。

大量笔记先由模型根据笔记内的召回路标和可见来源关系提出有意义的规划分组，再让各组完整读取其范围内笔记。候选问题只在完整笔记研究时帮助总编理解读者问题。代码不按固定数量、文件顺序或字符数分组。

门禁：项目再次停在“等待确认”。未经用户确认，不批量编写正式讲义。

### 第 3 阶段：讲义、全书收口与 Skill

输入：已确认的主题地图、编辑方案、各主题获准笔记和原文证据。

输出：并发准备的主题证据包；由总编模型串行形成和修订的正式讲义；全书一致性结论；导航；最终 `SKILL.md`；精选证据和来源映射。

最终发布目录只允许：

```text
SKILL.md
nav/
references/
wiki/
search/
sources.jsonl
```

`references/` 只保存支撑关键判断的原文片段和必要上下文，不复制整份可靠正文。项目 Prompt、笔记、Review、错误和进度不进入发布物。

门禁：系统先验证目录、引用映射和 Skill 可加载性，再原子晋升为候选成品。用户预览后手动启用；运行时只读取已发布 Skill。

## 后台与恢复

- API 先提交项目事实，再投递 ARQ。
- Worker 启动时扫描处于运行阶段的项目，并只重投未达到当前产物合同的材料或主题。
- ARQ job ID 对项目、材料和当前方法/组织版本保持稳定，用于避免重复投递；项目记录仍是完成与否的唯一依据。
- 模型调用始终显式组装当前任务所需完整输入，不让模型扫描项目目录或依赖会话记忆。
- 模型输出只做结构、必填关系和引用范围检查；内容质量交给独立 Review 和两次用户确认。
- 限流和临时连接失败做有限重试；笔记和讲义只允许一次有具体意见的自动修订。

## 前端用户流程

专家项目成为登录后扩展区的默认产品入口。列表只展示名称、材料范围、当前主阶段、总体进度和需要行动的问题。

项目详情按当前阶段展示：

- 材料清单和最多 20 份、多方向样本选择；
- 学习方案、笔记小样、Review 和第一次确认；
- 批量材料总体进度及需要处理明细；
- 主题方案、讲义小样、未纳入材料和第二次确认；
- 讲义进度、成品目录、精选证据预览和手动启用。

原始 Prompt 默认折叠，只供高级检查。内部 job、路径、重试次数和机器状态不占据主页面。

## 明确不做

- 不接入 Pi、Prime、Prime 工作台或高级问答；
- 不复制旧快速索引主链，不发布整份原文；
- 不使用 API 进程内 Tasker 恢复专家项目；
- 不引入通用 DAG、hash 审计链、dispatch/receipt 账本、多宿主调度或实验平台；
- 不用字数、关键词、标题数量等机械规则判断笔记或讲义质量；
- 不做 Python 包、环境变量、API 和数据库技术标识的全仓改名。
