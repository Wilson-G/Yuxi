# 编译底稿（内部，compilation_brief_markdown 模拟）

项目：Soju子晴 · 亚马逊站内运营与广告投放实战。本底稿是全部阶段 Prompt 的共同上游：运行时下游任务看不到本文，它们需要的领域框架、来源纪律和格式要求已完整内嵌进各自的 Prompt。

## 项目领域推导模型

### 模型来源与四层边界

这份模型先由模型已有的亚马逊站内运营知识激活成候选框架，再经五篇代表样本（M004 竞价策略、M008 小词带大词、M016 服装类目、M043 数据诊断 SOP、M044 ASIN 定位）校准。后续所有 Prompt 共用它，但必须分清四层：

- **领域基础**（模型已有稳定框架，可作补链依据）：SP/SB/SD 广告体系与各自归因周期差异；CPC、ACOS、TACOS、CTR、CVR 的定义与相互关系；TOS/ROS/PP 三类广告位；搜索加权来自买家的搜索、点击、购买，词根之间权重互通；变体合拆对流量入口的影响；库存预售与购物车机制；评论体系与合规红线的基本框架。
- **样本观察**（只属于样本资产，不代表整个材料包）：新手默认用只降低加固定竞价；瓶颈期靠预期坑产维持位置、主动降广告花费占比；竞价本质是在跟竞争对手竞价而非跟平台；标品流量词集中竞价高、非标词散竞价低；单量诊断先分自然单还是广告单再逐层下钻；断货伤不伤链接取决于断货前的数据输入。
- **项目假设**（待全部材料验证，不得写成已确认方法）：老师的底层方法论可以概括为「以干预单量为杠杆、以 CTR/CVR 数据质量为前提、按阶段推进并在瓶颈期主动收缩」；词根权重互通可能是贯穿全包的核心机制；「跟竞争对手竞价」可能统一解释多数竞价判断。
- **材料缺口**（追问与降调的依据）：利润核算口径几乎没有展开；站外流量与促销配合只有零星提及；SB/SBV/DSP 只有个别篇目；绝大多数打法没有前后数据对照；快问快答缺失原始提问。

### 推导链使用纪律

七条链是比较框架，不是内容清单。每个环节只用领域基础层的稳定关系，描述这一类局面需要分辨什么、依据什么证据形态分辨；代表材料的具体结论、数字和打法一律不写成分辨结果，归入样本观察层并标注待全部材料验证。局面清单本身可以由代表材料揭示（例如诊断顺序来自 M043），但链内的分辨逻辑保持框架级。单篇材料超出已知局面时，照常重建它的推导路径并在路由字段留下新局面路标，由总编完整阅读后决定是否升格为新局面。

### 判断局面一：新链接起步——先买什么流量

```text
当前任务或局面：新品或重推链接，预算有限，要决定先买什么流量。
-> 先观察什么：目标流量的词分布集中还是分散、预算规模相对目标位置竞争强度的差距、当前转化率水平、链接是全新还是有历史权重记录。
-> 候选判断：集中预算直接竞争目标大词 / 从低竞争长尾起步向大词传导 / 先用自动与商品投放摸清收录与词路。
-> 再检查什么区分：预算能支撑目标词要求的持续出单规模吗；当前转化率撑得起正面竞价吗；备选长尾与大词的词根共享度够不够支撑加权传导；平台对新链接的冷启动限制有哪些。
-> 什么结果让判断成立、削弱或反转：读数组合决定哪条候选的前提成立——预算与转化都撑得住，直接竞争的前提成立；任一不足则前提削弱，需要先在低竞争位置积累权重；目标大词长期低转说明尚不具备正面竞争条件，直接竞争前提反转——继续投入会同时拖累共享词根的表现。
-> 哪条判断支持哪个动作：哪条候选的前提被读数证实，就执行那条候选对应的动作方向；具体投放配置（词路取舍、否定、竞价结构）由各篇材料的资产提供，本链不预设。
-> 动作后看什么反馈：CTR/CVR 是否改善平台认定的链接质量、目标词自然位是否爬升、广告花费占比走向。
-> 什么情况下停止：排位长期停在某一区间拉不动时转入维持局面的判断——那时要分辨的是保位置靠投放时段安排还是靠出价水平、产品对广告位结构的依赖有多强。
```

### 判断局面二：单量异动诊断

```text
当前任务或局面：日常复盘发现单量异常。
-> 先观察什么：单量正不正常；不正常再看小时趋势——全天一起跌还是某个小时特别差。
-> 候选判断：自然单波动 / 广告单波动。
-> 再检查什么区分：自然单→自然位掉了吗，是否活动结束、涨价、快断货进预售；广告单→花费是不是变少了，花费没变则 ACOS 是否升高，再分 CPC 变高还是 CVR 变低，落到哪条广告、自己做了什么动作、平台有什么动作。
-> 什么结果让判断成立、削弱或反转：找到单一可解释因素且时间线吻合→成立；多个变量同时在动→降级为候选原因，继续拆数据窗口。
-> 哪条判断支持哪个动作：定位到哪一层就在哪一层动手——位子掉了推位子、CPC 贵了调竞价结构、CVR 掉了查承接与比价；不做跨层乱调。
-> 动作后看什么反馈：次日同口径数据回验；SP 记住 7 天归因窗口。
-> 什么情况下停止：归因窗口没走完或数据量太小，先记录不动手。
```

### 判断局面三：广告跑不动或数据差——异常排查

```text
当前任务或局面：广告没曝光、有点击没出单、ACOS 偏高、自动转手动后表现落差等异常。
-> 先观察什么：现象属于哪种形态，曝光量级、点击率、转化率的组合长什么样。
-> 候选判断：竞价与预算不够 / 匹配与否定设置错误 / 广告位分布不利 / listing 承接力不足 / 词与产品本身错配。
-> 再检查什么区分：三种指标的组合形态指向哪个方向；先确认读数干净——哪些表现已被平台代管功能或规则改动修改过（代调出价、默认勾选），被修改过的读数不能当作链接真实水平的依据；要做对比时还剩哪些变量在被平台自动改动。
-> 什么结果让判断成立、削弱或反转：哪个方向的数据形态吻合就先怀疑哪个方向；一次改动只验证一个方向，改完反而恶化说明该方向前提不成立，回退上一档重来。
-> 哪条判断支持哪个动作：动作跟着被证实的方向走，一次只动一个变量，留出干净的对比窗口；具体调整参数由各篇材料的资产提供。
-> 动作后看什么反馈：调整后完整归因周期的同口径对比。
-> 什么情况下停止：多轮排除仍指向产品竞争力本身时，停止在广告层面加码，转向价格、评论、页面或止损判断。
```

### 判断局面四：竞价策略与广告位控制权

```text
当前任务或局面：为广告活动选择出价控制方式（固定竞价、只降低、提高和降低、基于规则），并决定要不要启用广告位加价比例。
-> 先观察什么：链接处在测试期、成长期还是成熟期；此刻这个决定服务的是测试、爬坡还是维稳。
-> 候选判断：四种出价方式对应四种控制权让渡程度——从完全自己控制到完全交由平台代管；广告位加价比例是另一维度的让渡。
-> 再检查什么区分：近期要不要做竞价、广告位、词根或表现的对比测试——测试依赖未被修改的真实读数；谁有权改动你下一步判断所依赖的数据（自己还是平台）；当前管理精细度要求高还是低。
-> 什么结果让判断成立、削弱或反转：分辨主干只有一条——需要真实反馈时，任何由平台代改出价的方式都会污染读数，相关候选的前提被削弱；可以接受代管时，让渡换来的省心才成立。各阶段具体选哪种组合，由各篇材料的口径提供。
-> 哪条判断支持哪个动作：按「此刻要什么数据」选定控制方式，再决定广告位加价的幅度方向；具体搭配属于各篇资产。
-> 动作后看什么反馈：商品页曝光量变化、各词跑量情况、ACOS 与广告花费占比。
-> 什么情况下停止：发现平台侧规则又改动（如加价上限调整），把依赖该规则的配置降级为待检查项。
```

### 判断局面五：要词还是要位置——关键词投放与商品投放取舍

```text
当前任务或局面：决定预算投关键词还是投商品页（ASIN/类目），以及定投竞品页用来达成什么。
-> 先观察什么：我要的是这个词本身的排名与流量，还是这个词下面用户暴露的行为信号（曝光、点击、加购、购买落在哪些页面）；候选竞品页相对自己弱在哪里。
-> 候选判断：关键词定向 / 定投竞品截流 / 定投自家关联护位 / 借商品页表现给词加权 / 自动与类目拓量收词。
-> 再检查什么区分：两边在同一位上的出价差距；这个词的直接竞争值不值当前投入；搜索词绩效工具里商品投放实际带出了哪些词；自己的类目结构与变体宽度适合哪种互相喂养。
-> 什么结果让判断成立、削弱或反转：竞品存在明确弱点且价差有利，截流候选的前提成立；找不到弱点则前提削弱；商品投放会跑到未定向词——这既是噪音来源也是批量发现新词的通道，两个读数要一起称重。
-> 哪条判断支持哪个动作：动作跟随被证实的用途——要词、要位置还是要收词，路径完全不同；具体投放组合由各篇材料的资产提供。
-> 动作后看什么反馈：这些动作带来的词有没有体现为搜索结果位的出现与出单。
-> 什么情况下停止：某竞品页自身转化很差、投入无产出时撤出该位置。
```

### 判断局面六：品类形态与打法预期

```text
当前任务或局面：接手一个品类或规划新品，先判品类形态再谈打法。
-> 先观察什么：流量词集中还是分散、准词多还是泛词多、头部有没有品牌垄断、自己的价格与资源处在哪一档。
-> 候选判断：集中词正面竞争的标品路径 / 中间形态 / 找细分小词避开正面竞争的非标路径。
-> 再检查什么区分：广告位按出价竞争分配，流量越集中、竞争者越挤在同一批词上，价格信号越强——据此读目标词的实际成交价水平；非标词分散但把成败压在选款与供应链上；把品类形态、自身价格优势、品牌力三项读数放在一起，才看得出可行路径。
-> 什么结果让判断成立、削弱或反转：三项读数缺哪一项，对应路径的前提就缺一角；全部不利时正面竞争的前提反转，应重新评估赛道选择。
-> 哪条判断支持哪个动作：形态读数决定竞争主轴——拼位次还是拼差异化，选款、定价、词路与推广强度的配置跟着主轴走；具体配置由各篇材料的资产提供。
-> 动作后看什么反馈：实际成交竞价与预期位置的匹配程度。
-> 什么情况下停止：长期投入仍拼不过头部组合时，承认赛道错配，评估换细分或退出。
```

### 判断局面七：断货、涨价与数据卫生

```text
当前任务或局面：断货前后怎么办，涨价或压库存时如何保护链接。
-> 先观察什么：断货是被迫还是计划内；断货之前链接的数据轨迹好不好；品类季节性走到哪一段。
-> 候选判断：不惜代价防断货 / 接受计划内断货等待更好时机 / 断货后按恢复路径处理。
-> 再检查什么区分：断货造成的空窗与断货前后操作输入的数据质量是两个变量，混在一起会误判；链接历史表现数据怎样影响恢复速度；季节曲线上错过的时间窗有多大。
-> 什么结果让判断成立、削弱或反转：读数显示伤害主要来自操作输入而非空窗本身时，「不惜代价防断货」候选的前提被削弱；被动断货且轨迹已差时进入修复路径的评估。
-> 哪条判断支持哪个动作：动作跟随归因结果——空窗问题走节奏安排，数据质量问题先停污染源；具体操作由各篇材料的资产提供。
-> 动作后看什么反馈：恢复期的自然位与 CVR 能否回到断货前水平。
-> 什么情况下停止：任何以损害历史数据真实性为代价换取短期库存或销量目标的操作，立即触发停止线。
```

### 审查另一位专家（观察者身份）

编译每一篇材料时都要用这套问题审查老师本人：

- 他是否跳过中间关系直接下了结论（断言式金句）；
- 他是否把一次经验说成了普遍规律；
- 他有没有写反平台因果（例如把「平台按产出分配位置」说成「位置靠抢就行」）；
- 他的固定数字有没有条件和时效；
- 他是在替卖家判断还是在替平台利益说话（后台建议竞价、默认勾选的策略）；
- 他建议的动作强度有没有超过他给出的证据强度。

## 材料校准结论

- M004（竞价策略）校准了局面四：老师按「控制权」而不是按好坏给四种策略排序；「新手无脑用只降低和固定竞价」「新品开只降低会测出虚高竞价」进入样本观察层。
- M008（小词带大词）校准了局面一：确认了「先推排名再做利润」的前提、干预单量的概念、瓶颈期两种收缩方式与「挑不挑广告位」的二选一口径。
- M016（服装类目）校准了局面六：给出「竞价是跟竞争对手竞价」的原话、标品与非标的竞价区间经验值（数字带时效）、以及品类形态决定打法顺序的实例。
- M043（数据诊断 SOP）校准了局面二：完整的单量诊断顺序来自这一篇；同时暴露后台指标词汇的转写噪音问题（ACOS/TACOS/CPO/CPU 多种错拼）。
- M044（ASIN 定位）校准了局面五：进攻防守加权三分法、「买家搜词点进竞品再点进我也能在该词加权」的机制主张、商品投放批量收词的用法。
- 五篇共同确认：材料语言高度口语化、术语错拼密集、大量断言无反馈数据——这决定了来源标签必须逐节点拆，不能整篇定性。

## 资产编译规范

### 五类来源标签

- `原文明说`：材料直接给出的事实、定义、公式、判断、动作、反馈或预测。只代表归属清楚，不代表内容正确或专业。例：「我建议所有新手无脑使用只降低和固定竞价。」
- `领域补链`：依据输入事实和稳定领域关系补出的必要中间步骤，不得冒充作者原话；存在多个同样合理的机制时不写成确定补链。例：从「让平台认识到 CTR 和 CVR 是好的」补出「平台以点击率与转化率作为链接质量信号分配自然位」。
- `候选解释`：能解释观察但存在其他合理机制、或材料条件不足以排除其他机制的解释；必须降调，不能单独支撑强动作。例：「广告烧得越多自然单越少」可能成立，但也可能是大盘流量波动。
- `专家质疑`：指出算式矛盾、反领域关系、遗漏条件、错误因果、过期规则、过强动作或不专业步骤；保留被质疑的原始说法，不静默替作者改口。例：「服装竞价普遍 0.2~0.7 美元」缺少类目与时间范围。
- `材料未知`：材料没有给出、无法唯一推出或尚未得到反馈的部分；未知是停止、追问或降调的依据，不能用合理猜测填满。例：低价螺旋对新品长期权重的影响，材料没有提供回验。

一个节点只能有一个标签；原话、补链、候选解释和质疑混在同一句时拆成多个节点。

### 单篇资产结构

`note_markdown` 固定包含 `## 资产定位`、`## 资产节点目录`、`## 资产正文`、`## CoT 推导示范` 四段；目录条目（N01 起，含节点类型与来源标签）与正文三级标题同序一一对应，摘要单行。节点类型按真实内容选用：输入事实、关键观察、连续推导、条件分支、反转/停止、动作、反馈/回验、预测/未知、可迁移检查、专家质疑；材料没有反馈就不建反馈节点，没有预测就不建预测节点。CoT 推导示范按 `Input -> Goal / Constraints -> Observation -> Domain Relation -> Inference -> Next Check -> 新观察或反馈 -> Update -> Branch / Stop -> Action -> Transfer` 组织，每一步由前一步触发；没有的环节明确写没有。

本项目特有的两条纪律：

1. **先还原术语再归属**：转写错字（大慈=大词、A森=ASIN、a call ass=ACOS 等）按上下文还原；还原动作记为 `领域补链`，还原后的老师主张才记为 `原文明说`。
2. **时效数字标注条件**：平台侧数字（加价上限、竞价区间、规则条款）保留在 `原文明说` 节点内并注明「当时的平台状态」，需要外部核实时进入 `材料未知` 或 `专家质疑`。

### 各阶段职责与交接

1. `note_author` 观察老师、重建推导路径、产出单篇资产 → 2. `note_reviewer` 独立对照原文复核来源与关系 → 3. `note_reviser` 只落实接受的修订 → 4. `topic_researcher` 全局用路由路标分组、组内完整阅读提候选主题 → 5. `topic_editor` 总编定主题地图，保留分歧 → 6. `handout_editor` 编讲义（判断主干 + 条件分支 + 反转停止 + 反馈修正）→ 7. `handout_reviewer` 独立查混源、丢分支、丢质疑 → 8. `handout_reviser` 定点修订 → 9. `book_editor` 全书一致性收口 → 10. `navigation_author` 按读者局面做导航 → 11. `skill_author` 生成带专家身份的使用入口。

### Review 标准（硬问题清单）

Reviewer 只报告会让下游学错或做错的问题：原文主张被补链覆盖或静默改写；补链方向写反或存在并列机制却写成唯一解释；案例相关性升级为唯一因果；固定数字缺条件或缺时效；强动作建立在候选解释上；目录与正文不一致；CoT 退化成检查项清单；Author 罗列领域通用检查项而没有重建老师实际路径；evidence 为非原文明说节点伪造行号。链更长不等于质量更高。

### 最终回答边界

成品讲义与 Skill 面向最终用户自然表达：不输出节点 ID、五类来源标签、Thought/Action、审计锚点、文件路径或编译说明；关键依据和条件可以自然解释。用户输入事实高于任何相似案例；候选解释不给强动作；材料未知时收窄结论或说明需要什么输入，不用免责声明填篇幅。
