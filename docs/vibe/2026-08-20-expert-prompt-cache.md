# 专家模型任务复用 Prompt Cache

日期：2026-08-20

## 目标

专家项目批量处理材料和主题时，把同一项目版本反复使用的阶段 Prompt、学习方案和响应合同放在稳定 System 前缀中。每份材料仍由独立 ARQ 工作完整读取，不共享对话历史，也不恢复项目进程内的并发调度。

## 当前边界

- 只对已经验证的 OpenAI 协议 `gpt-5.6-*` 模型发送 `prompt_cache_key`、`prompt_cache_options.mode=explicit` 和 System 内容块断点。
- 缓存键由项目方法或组织版本、响应合同和完整 System 前缀共同决定；材料正文、笔记和证据留在后续变量消息中。
- Author、Reviewer、Repair、候选主题研究和主题证据准备使用缓存；一次性定向、主题地图、总编讲义和全书收口不使用。
- 不发送额外种子请求，不预设缓存分片，不新增开关。首个真实请求写入缓存，后续相同前缀请求自然复用。
- 是否命中以供应商返回的 `usage_metadata.input_token_details.cache_read` 为准，并写入 Worker 日志。
- 其他 OpenAI 兼容端点和模型保持原请求参数，不假定支持相同协议。

## 验收

- 同一项目版本、任务类型生成相同缓存键，不同响应合同生成不同键。
- 每个独立任务仍发送自己的完整材料或主题输入。
- `langchain-openai` 实际请求序列化包含缓存键、显式模式和内容块断点。
- 未验证模型不携带缓存参数。
- 资料库材料关联、单材料 ARQ job、Worker 恢复和两个确认点不变。
