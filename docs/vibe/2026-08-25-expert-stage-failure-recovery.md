# 专家项目失败分流与阶段自愈补齐

日期：2026-08-25

状态：已评审实施方案。本文是对「专家项目总是卡住」诊断的独立核实结论与实施边界，作为本次改造的验收依据。

## 背景与核实结论

2026-08-25 现场 5 个项目卡住，代码与数据库核实后确认四个根因全部属实：

| 项目 | 阶段 | 根因归类 |
| --- | --- | --- |
| ama（人工） | organization / needs_attention | 主题地图校验（ValueError）直接击穿整阶段任务，无带反馈重试 |
| ama2、老韩命理（自动） | organization / needs_attention | 存量病笔记（结构门上线前学习、无资产节点目录或目录与正文不同序）在组织入口复检时击穿整阶段；现有「按意见重新生成」不改变笔记，重跑必崩，项目被砖死 |
| Amazon（自动） | handout_compilation / needs_attention | 429 等瞬时错误被 `write_topic_handout` 的 `except Exception` 吞成主题级永久失败，外层重试与重投均不可见（2 个主题被原始 429 钉死）；另有 2 个主题为 Review 内容意见修订后未通过，属共识允许的停机 |
| 老韩8（自动） | orientation / running | 方法校准单次调用 30~50 分钟，任务级重试退避仅 2/4/8/16 秒；定向与单材料学习有 45 分钟错峰自动重投，校准/组织/讲义三个入口都没有 |

关键事实：现有代码已经具备阶段内原子性（材料按份、研究按批、讲义按篇、规划分组与主题地图先落库再续跑），「原子化重构 runner」不是缺口；缺口是**失败分流没有贯彻到第 2、3 阶段和方法校准**：瞬时故障被吞、确定性校验失败无反馈重试、传输故障烧尽秒级预算后无错峰重投。

## 与共识文档的关系

本方案不改变 [2026-08-18 意图冻结](2026-08-18-expert-learning-pipeline-intent.md) 的任何用户流程：

- 底线 18（自动重试和修订必须有限）：所有新增重试都有界（校验反馈重试 ≤2 次、错峰重投 24h 内 ≤6 轮）。
- 底线 8 与第 3 阶段约定（讲义在预算内无法交付即按运行条件失效停止）：**不引入讲义 Review 的自动终裁**；内容性停机保持，只有瞬时故障改走自动重试。
- 底线 15（ARQ 负责执行）：**不引入常驻 runner、DAG 编排、长生成检查点或独立模型健康子系统**；错峰重投沿用现有 ARQ 延迟任务模式。

结构修复沿用学习阶段既有先例（`_apply_asset_note_structure_gate`：结构合同是确定性输出合同，合成 revise 意见交回修订循环，人工模式同样自动修复，不中断流程）。

## 实施内容

1. **瞬时错误判定共享化**：`_is_transient_material_error` 从 worker 迁至 `model_tasks.is_transient_expert_error`，供组织/讲义服务层复用。
2. **组织阶段校验失败带反馈重试**：`plan_note_groups`、`edit_topic_map` 增加 `validation_feedback` 参数；`run_organization_stage` 对两处校验 ValueError 执行 ≤2 次带反馈重试，耗尽后维持现有 needs_attention 语义。已有落库产物（分组、研究批次、主题地图）不重跑。
3. **组织入口病笔记自动修复**：资产方法项目在组装笔记目录前，对每份已通过笔记先规范化并校验结构；不合格的按学习阶段同一修订模式（合成结构 revise 意见 → 有界修订 → 复核）自动修复并回写材料；仍不合格的材料落 needs_attention 并从本次组织输入中移除；全部不可用则明确停止。
4. **讲义阶段瞬时分流**：`write_topic_handout`、`prepare_topic_evidence`、`_revise_topic_from_book_review` 中瞬时错误改抛出（主题保持 writing，可自然续跑），确定性错误维持现有主题级 needs_attention；`_research_one_batch` 同样不再把瞬时错误沉淀为批次 needs_attention。
5. **错峰自动重投补齐**：方法校准、组织、讲义编译三个任务在瞬时故障烧尽任务级预算后，安排 45 分钟后错峰重投（24h 内 6 轮上限，与定向/单材料同节奏）；重投任务带版本与状态守卫，现场已变（用户已重开、版本已推进、已暂停）则忽略。确定性业务失败不触发重投。

## 验收标准

1. 主题地图遗漏笔记类校验失败：自动带反馈重试 ≤2 次；仍失败时错误信息具体可行动；已完成分组与批次研究不重跑。
2. ama2 / 老韩命理类项目：重新触发组织阶段后病笔记被自动修复或落为单材料 needs_attention，组织阶段不再因存量笔记整阶段死亡；笔记全部不可用时给出明确原因。
3. 讲义阶段遇到 429/断连：不再出现主题被原始 429 错误钉死；瞬时故障经任务级重试 + 错峰重投自动恢复，内容性 Review 停机行为不变。
4. 校准/组织/讲义传输故障烧尽预算后项目先落 needs_attention 并展示错峰重投安排，45 分钟后自动续跑；24h 内 6 轮耗尽后停止等人工。
5. 用户在中途的任何人工动作（反馈重开、暂停、版本推进）使对应重投任务安全忽略。
6. 现有全部专家单元/集成测试通过；新增测试覆盖上述路径。
